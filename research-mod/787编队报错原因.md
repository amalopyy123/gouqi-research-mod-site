# Actor 787 编队报错原因

## 结论

Actor ID `787`（`ノーライフキング`）本身的职业、种族默认值、初始装备、技能和图像记录均存在。它不能进入编队的直接原因不是角色数据缺失，而是原版编队界面的类别排序没有处理未登记类别。

## 错误日志

`errors.txt` 在 `2026-08-15 10:51:48` 及后续测试中记录：

```text
Exception : ArgumentError
comparison of Fixnum with nil failed
```

调用栈定位到：

```text
(画面/パーティ編成)：467:in `sort_by'
(画面/パーティ編成)：467:in `sort_by!'
(画面/パーティ編成)：467:in `make_actor_categories'
```

对应提取脚本：`研究修改器/候选脚本/0152__.rb:467`。

## 原版逻辑

原版编队界面按类别排序时使用：

```ruby
@actor_categories.sort_by! { |category| NWConst::PTEdit::CATEGORY_PRIORITY.index(category) }
```

如果类别不在 `NWConst::PTEdit::CATEGORY_PRIORITY` 中，`index` 会返回 `nil`。Ruby 无法比较数字排序键和 `nil`，于是抛出上述 `ArgumentError`。

## Actor 787 的触发条件

Actor `787` 的备注包含以下类别：

```text
<カテゴリー：サキュバス>
<カテゴリー：ゾンビ>
```

原版优先级表包含 `:ゾンビ`，但不包含 `:サキュバス`。因此 `:サキュバス` 的排序键为 `nil`，打开编队界面时立即报错。

## 当前 Mod 修复

`Patch/zzz_Research_Mod.rb` 和发布副本会仅对 Actor `787` 在运行时应用以下替换：

```ruby
priority = NWConst::PTEdit::CATEGORY_PRIORITY
@actor_categories.sort_by! do |category|
  [priority.index(category) || priority.size, category.to_s]
end
```

该替换不会修改 `Data/Actors.rvdata2`。如果原始数据库中的类别仍为 `サキュバス`，编队界面实际收到的类别会是 `淫魔`；如果数据库已经改成 `淫魔`，结果保持不变。

## 验证状态

- 两份 Mod 脚本均通过 `ruby -c` 语法检查。
- 不需要再修改数据库；应以 Actor `787` 打开编队界面进行运行时确认。

## 数据库修改后的复查（2026-08-15）

- 已确认 `Data/Actors.rvdata2` 中 Actor `787` 的类别为 `淫魔` 和 `ゾンビ`。
- 这两个类别均存在于原版 `NWConst::PTEdit::CATEGORY_PRIORITY`。
- 已扫描全部 Actor 的 `カテゴリー` 标签，当前没有任何类别未登记在该优先级表中。
- 即使将数据库恢复为 `サキュバス`，当前 Mod 也会在运行时转换该类别，因此编队脚本第 467 行不应再因 Actor `787` 的类别排序出现 `comparison of Fixnum with nil failed`。
- 如果仍看到该错误，优先确认游戏已完全关闭后重新启动，并确认启动的是本目录的游戏；已运行的 RGSS3 进程不会自动重新读取修改后的脚本。
