# 文案生成网页模板

这个目录保存当前 Mod 介绍页的可复用模板。它沿用现有页面的视觉样式：单列从上到下显示、图片较大、图片可以点击放大，并且支持“文字 → 图片 → 文字 → 图片”的原文顺序。

## 文件说明

- `index.html`：页面结构模板。修改标题、项目名称、安装提示和注意事项。
- `template-data.js`：主要内容数据。把文案拆成一个个功能卡片，每个卡片用 `flow` 保留原文顺序。
- `content-flow.template.js`：根据 `template-data.js` 生成文字和图片。一般不需要修改。
- `styles.css`：当前页面基础样式。
- `layout-overrides.css`：单列布局和大图样式。一般不需要修改。
- `guide.js`：图片点击放大功能。一般不需要修改。
- `images/v1.0/`、`images/v1.1/`、`images/v1.2/`：按版本保存截图。可以增加新的版本目录。

## 新内容的标准写法

在 `template-data.js` 中，每个功能写成：

```js
{
  title: "更新 10（保留原文标题）",
  flow: [
    { type: "text", value: "第一段原文" },
    { type: "image", version: "v1.2", file: "查询鲁卡图片.png", alt: "查询鲁卡图片" },
    { type: "text", value: "图片之后的原文" },
    { type: "image", version: "v1.2", file: "图片资源替换1.png", alt: "图片资源替换1" }
  ]
}
```

原则：

1. 只从用户指定的文案文件读取内容；没有指定的旧文案不要混用。
2. 尽量逐字保留原文，不要把长段落概括成摘要。
3. 文案中的图片标记出现在哪里，就在对应位置插入图片。
4. 图片文件名必须和实际文件名完全一致，包括扩展名和大小写。
5. 先检查全部图片是否存在，再生成页面；发现缺失、重名或编码问题要记录到 `ISSUES.md`。

## 线上版和离线版

生成完成后，将模板目录中的网页文件、脚本、样式和 `images/` 复制到两个位置：

- Cloudflare Pages 仓库中的说明页目录，例如 `mod-guide/`。
- Mod 文件夹中的离线目录，例如 `mod功能介绍（请提前看）/`。

离线版可以直接双击 `index.html`（或用户指定的 HTML 文件）。图片使用相对路径，不要写绝对路径。线上版可以通过 Pages 部署，静态页面不需要构建命令。

## 新开对话时可以直接发送的说明

将下面这段文字和新的文案、图片一起提供给 ChatGPT：

> 请使用仓库中的 `git文件/gouqi-research-mod-site/mod-guide-template/` 模板生成 Mod 说明网页。只使用我明确指定的文案文件，忽略旧文案。保持现有单列、大图、点击放大样式；文字和图片必须严格按原文出现顺序穿插，不要擅自概括或省略。图片按版本放入 `images/vX.Y/`，同时生成 Cloudflare Pages 版和 Mod 文件夹离线版。请先检查文案编码和所有图片引用，发现问题写入 `ISSUES.md`，最后报告修改文件、图片数量和缺失检查结果。代码注释使用英文。

如果页面不应出现下载链接，请额外写：

> 说明页不要包含百度云、GitHub、提取码、解压密码或任何下载链接。

## 更新检查清单

- [ ] 文案来源文件已明确，旧版本文件未误用。
- [ ] 原文标题和段落没有被无意改写。
- [ ] 每张图片都存在且路径大小写正确。
- [ ] 图片顺序与文案中的标记顺序一致。
- [ ] 线上版和离线版使用同一份内容。
- [ ] 页面不含不希望公开的链接或密码。
- [ ] `node --check` 通过所有 JavaScript 文件。
- [ ] `ISSUES.md` 已记录生成期间遇到的问题。
